# AIL Errors Register (Common Template)

Назначение: шаблон общего реестра ошибок AIL для повторного использования в разных проектах.

## Правила ведения

1. Писать только проверенные ошибки из реальных сессий.
2. Формат пункта: `Симптом -> Причина -> Правило предотвращения`.
3. Формулировать коротко и проверяемо.
4. Не удалять старые пункты без причины; допускается уточнение.
5. Обновления реестра фиксировать в `ailog.md`.

## Универсальные ошибки "не повторять"

1. Преждевременное завершение задачи.
   - Правило: не отвечать "готово", пока не подтвержден полный пользовательский сценарий.

2. Проверка только одного слоя системы.
   - Правило: всегда сверять минимум 2 независимых источника (код + runtime, runtime + внешние данные).

3. Неподтвержденные изменения в рабочем дереве.
   - Правило: после критичных изменений проверять целевые файлы и итоговый `git diff`.

4. Пропуск негативных/граничных проверок.
   - Правило: кроме happy-path, проверять хотя бы один отказной/пограничный кейс.

5. Потеря контекста между сессиями.
   - Правило: фиксировать решения, риски и незавершенные действия в `ailog.md`.

## Универсальный pre-finish чеклист

- Выполнен сценарий пользователя end-to-end.
- Результат подтвержден технически (тест/лог/факт поведения).
- Риски и ограничения явно описаны.
- Контекст сессии зафиксирован в AIL-документах.
